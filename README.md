## 1. Project Overview

เรื่องเล่า ความรู้ และคำสอนของผู้สูงอายุหายไปพร้อมกับท่าน
เพราะลูกหลานไม่มีเวลานั่งฟัง ไม่รู้จะเริ่มถามอะไร และไม่มีเครื่องมือเก็บรักษา

**เล่าไว้** ยกภาระทั้งหมดมาไว้ที่ลูกหลาน แล้วปล่อยให้ผู้สูงอายุทำสิ่งที่ท่านเก่งที่สุด — เล่า

หลานนั่งข้างท่าน เปิดคำถามจากชุดคำถามตามช่วงชีวิต กดอัดทีละ 1–3 นาที
AI ถอดเสียง ดึงประเด็น และเสนอคำถามต่อจากสิ่งที่ท่านเพิ่งเล่า
จบหัวข้อแล้วเรียบเรียงเป็นบทหนังสือ ครอบครัวตรวจและยืนยัน
แล้วได้หนังสือ A5 ที่ทุกย่อหน้ามี QR ให้สแกนฟังเสียงจริงของท่าน

### 🔑 สิ่งที่ทำให้โปรเจกต์นี้ไม่ใช่ ChatGPT wrapper

> **ทุกย่อหน้าในหนังสือต้องอ้าง Claim ที่มีถ้อยคำต้นฉบับอยู่จริงในข้อความถอดเสียง
> และเราตรวจด้วยโค้ด ไม่ใช่ให้ AI ตรวจ AI**

ถ้าหาถ้อยคำนั้นไม่เจอในเสียงจริง → **ระบบทิ้งทันที ไม่ให้เข้าหนังสือ**
ประโยคที่ AI เขียนเกิน → **ไฮไลต์เหลืองให้ครอบครัวตัดสินใจก่อนพิมพ์**

หัวใจอยู่ใน [`lib/verify.ts`](lib/verify.ts) และพิสูจน์ได้ด้วย `npm run check`

### หัวใจของระบบ — [`lib/verify.ts`](lib/verify.ts)

```ts
export function normalizeThai(s: string): string {
  return s
    .normalize("NFC")
    .replace(/[\s ​‌‍]/g, "")
    .replace(/[.,!?;:"'`""''()\[\]{}…ฯ]/g, "")
    .replace(/ๆ/g, "");          // ๆ — Gemini ใส่/ตัดไม่ตรงกัน
}

export function verifyClaim(transcript: string, quote: string): boolean {
  const q = normalizeThai(quote);
  if (q.length < 8) return false;      // กัน AI คืน quote สั้นจู๋อย่าง "ยาย"
  return normalizeThai(transcript).includes(q);
}
```

เรา normalize **เฉพาะช่องว่างกับเครื่องหมายวรรคตอน** ไม่แตะสระหรือวรรณยุกต์
เพราะถ้าแตะ AI จะแต่งคำใหม่แล้วยังผ่านได้

## 6. Setup / Run Instructions

```bash
git clone https://github.com/nickkeepgoing/laowai.git
cd laowai
npm install
cp .env.example .env.local      # แล้วเติมค่า
npm run dev                      # http://localhost:3000
```

**ยังไม่มี key ก็รันได้** — ระบบตรวจเองว่ามี Gemini/Supabase ไหม
ถ้าไม่มีจะถอยไปใช้ mock + in-memory store อัตโนมัติ และ flow ทั้งหมดยังเดินครบ

### ตั้งค่าให้ใช้งานจริง

1. **Supabase** → สร้าง project → SQL Editor → รัน [`supabase/schema.sql`](supabase/schema.sql) ทั้งไฟล์
   (ไฟล์เดียวจบ: สร้างตาราง · GRANT สิทธิ์ · สร้าง bucket · ตั้ง RLS — รันซ้ำได้ปลอดภัย)
2. **Gemini API key** → https://aistudio.google.com/apikey
3. **Google OAuth** (ถ้าต้องการปุ่ม Google) → Supabase → Authentication → Providers → Google
   redirect URI: `https://<project>.supabase.co/auth/v1/callback`

## 7. ⚠️ Current Limitations — สิ่งที่ยังไม่จริง

เราเขียนส่วนนี้ตรงไปตรงมา เพราะโปรเจกต์นี้ทั้งโปรเจกต์ตั้งอยู่บนหลักว่า
**อย่าอ้างสิ่งที่พิสูจน์ไม่ได้**

| เรื่อง | สถานะจริง |
|---|---|
| 🔴 **ไฟล์เสียงตัวอย่าง** | `public/demo/*.wav` เป็น**เสียงสังเคราะห์ ไม่ใช่เสียงคน** สร้างด้วย `scripts/gen-placeholder-audio.mjs` เพื่อให้ build UI ได้ ยังไม่ได้แทนด้วยเสียงจริงของปู่ย่าตายาย |
| 🔴 **ความแม่นภาษาถิ่น** | **ยังไม่ได้วัดกับเสียงผู้สูงอายุจริง** ภาษาอีสานมีงานวิจัยอ้างอิง (Typhoon ASR, CER 8.85%) แต่ภาคเหนือและใต้ยังไม่มีผลทดสอบ **เราจึงไม่เคลมว่ารองรับทุกภาษาถิ่น** |
| 🟠 **RLS** | `INSERT/UPDATE/DELETE` จำกัดเฉพาะเจ้าของแล้ว แต่ `SELECT` ยังเปิด เพราะ QR ในหนังสือต้องให้คนนอกสแกนฟังได้ ความปลอดภัยมาจาก `share_token` ที่เดาไม่ได้และเพิกถอนได้ **ยังไม่เหมาะกับข้อมูลครอบครัวจริงของคนนอกทีม** |
| 🟠 **Dialect Flywheel** | กลไกทำงานแล้วและเก็บข้อมูลจริง แต่**ยังไม่ได้เอา dataset ไป fine-tune โมเดล** — เป็น roadmap ไม่ใช่ของที่ทำเสร็จ |
| 🟠 **ภาพบนหน้าเว็บ** | ภาพถ่ายมาจาก Unsplash เป็น**ภาพประกอบ ไม่ใช่ผู้ใช้จริงของเรา** (ดู [`public/img/CREDITS.md`](public/img/CREDITS.md)) |
| 🟡 **ราคา** | ยังไม่มีตัวเลข เพราะยังไม่ได้ต้นทุนพิมพ์จริงและยังไม่ได้ทดสอบความเต็มใจจ่าย |
| 🟡 **ระบบชำระเงิน** | ยังไม่มี |
| 🟡 **การทดสอบ** | มี `npm run check` ตรวจความถูกต้องของสัญญาข้อมูล แต่**ยังไม่มี unit test suite เต็มรูปแบบ** |
| 🟡 **ผู้สูงอายุที่มีภาวะสมองเสื่อม** | ออกแบบแนวทางไว้แล้ว (ผู้ดูแลยินยอมร่วม · ปิดการเผยแพร่) แต่**ยังไม่ได้ลงมือทำในโค้ด** |
| 🟡 **Gemini latency** | 3.4 วินาทีกับเสียง 40 วินาที ยังไม่ได้วัดกับเสียง 3 นาทีเต็ม |

## 8. การตัดสินใจทางเทคนิคที่สำคัญ

<summary><b>ทำไมไม่ใช้ react-pdf ทำหนังสือ</b></summary>

react-pdf ไม่รองรับ complex text shaping ของภาษาไทย
สระบน-ล่างและวรรณยุกต์จะซ้อนผิดตำแหน่ง (เช่น "สื่อ" "ปู่" "ก๊อง") และตัดบรรทัดกลางคำ

เราใช้ HTML + `@media print` + `@page { size: A5 }` แทน ซึ่งใช้ text shaping engine
ของเบราว์เซอร์ที่ทำภาษาไทยถูกต้อง 100% กด Ctrl+P → Save as PDF ได้เล่มที่สวยกว่าและเร็วกว่า

<details>
<summary><b>ทำไมปิด thinking ของ Gemini</b></summary>

วัดจริง: **236 วินาที → 3.4 วินาที** (เร็วขึ้น 70 เท่า)

`gemini-2.5-flash` เผา thinking token หนักมากตอนเจอเสียงที่ฟังไม่ชัด
ซึ่งเสียงผู้สูงอายุพูดเบามีเสียงรบกวนจะเข้าเคสนี้เต็ม ๆ
งานถอดเสียงไม่ต้องใช้การให้เหตุผล จึงตั้ง `thinkingConfig: { thinkingBudget: 0 }`

และต้องบังคับ `httpOptions.apiVersion = "v1beta"` ไม่งั้น `responseSchema` ตอบ 400 กลับมา
</details>

<details>
<summary><b>ทำไม claim id ต้องมี nonce</b></summary>

เจอตอนทดสอบจริง: Gemini คืน id เป็น `c1, c2, c3` ทุกคลิป
แต่ `/api/compose` รวม claim จากทุกคลิปในหัวข้อเดียวกัน → id ชนกัน

ผลคือ **กดปุ่มลืมคลิปที่ 2 แล้วย่อหน้าของคลิปที่ 1 หายไป 5 ย่อหน้า**
แก้ด้วยการเติม nonce prefix ตอนรับผลจาก Gemini
</details>

<details>
<summary><b>ทำไมเก็บ correction เฉพาะคู่ข้อความ</b></summary>

เราประกาศไว้ว่า "ไม่นำเสียงไปฝึกโมเดลโดยไม่มีความยินยอมแยกต่างหาก"
ถ้าเก็บเสียงเข้า dataset แบบเงียบ ๆ เราก็ขัดคำพูดตัวเอง

ค่าตั้งต้นจึงเก็บเฉพาะ `asr_text → human_text` + ภาค
**ไม่เก็บเสียง ไม่เก็บชื่อ ไม่ผูกกลับไปที่คลิป**
จะผูก `clip_id` ได้ต่อเมื่อครอบครัวติ๊กยินยอมแยกที่หน้าตรวจ
และ `/api/forget` ลบ correction ของคลิปนั้นด้วย
</details>

<details>
<summary><b>ทำไมฟอนต์ต้องอยู่บน &lt;html&gt; ไม่ใช่ &lt;body&gt;</b></summary>

`next/font` ใส่ตัวแปรไว้ที่ className ที่เราวาง แต่ Tailwind v4 ประกาศ `--font-sans`
ไว้ที่ `:root` โดยอ้าง `var(--font-...)` — ถ้าตัวแปรอยู่บน `body` ตอน `:root` resolve
จะหาไม่เจอ ค่ากลายเป็น invalid แล้ว**ทั้งเว็บตกไปใช้ฟอนต์ default ของเบราว์เซอร์
โดยไม่มี error ใด ๆ ให้เห็น** ทั้ง build และ console ผ่านหมด
</details>
